## Durable entity lifetimes and protocol 23 — 2026-09-12

Coordinated workers now use durable, never-reissued entity blocks instead of restarting logical 32-bit namespace cursors. SQLite stores a global allocation sequence, immutable process/planet/region bindings and one issuance row per reservation batch. Each 65,536-ID block lies above the legacy 32-bit range; the final safe JavaScript integer is an explicit bound. Worker startup reserves eight blocks before constructing Game. The local synchronous pool spans bots, hulls, projectiles, pickups and wildlife, prefetching when two blocks remain. It never wraps, fills another worker's gap or waits for a per-shot database write. Late replies to closed pools are discarded and unused ranges are never reclaimed.

Bootstrap response-loss retries require the same unregistered process and request. Registered or retired IDs cannot bootstrap again. Refills require current authority, including cached receipts; transient retries retain the request ID. The normal cluster already creates a fresh UUID for every process start. The construction browser restart fixture now follows that contract too, and DEPLOY.md states it explicitly for remote worker launchers.

Protocol 23 uses canonical base-128 entity references throughout snapshots, projectile ownership, crew hull references, join/leave, scores, combat events, chat player IDs and construction actions. Malformed, noncanonical and unsafe values are rejected by the integer codec. Human IDs remain durable low 31-bit values; command sequences, seeds and chat message counters retain their separate 32-bit formats. Small human IDs shrink on the wire, new dynamic IDs initially occupy five bytes, and a maximum-width reference occupies eight. The 18-creature interest cap remains; its worst-case full-width tail is 450 bytes. Source movement and physics files retain their prior hashes.

The regional protocol checks a new hull's initial provenance against the issuance ledger, then follows its committed ownership. A regression migrates a real aircraft crew and live bombs, replaces the original source, spawns local hulls/bots/projectiles/wildlife, and brings the original crew back alongside those objects. Actor-identity guards prevent an old socket close from deleting a returned actor or resetting its chat limit; lease-identity guards preserve the returned character's new lease and launch. Another audit bounded cosmetic random/animation inputs: enormous IDs must not make wildlife steering and footstep animation too imprecise to respond to small changes. Server idle phases are checked against exact BigInt arithmetic at the safe-integer ceiling.
